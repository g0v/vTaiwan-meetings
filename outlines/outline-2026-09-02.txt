### 二、議題分享（第一小時）
* **講者**：昱均（受邀分享者）  
* **需要準備**：  
  - 相關背景資料與簡報  
  - 上一次活動的回顧報告（包括共識、分歧點）  
* **目的**：設定討論基調，讓參與者了解前置情境。

---

### 三、政策討論與分組安排（第二小時）
| 需求 | 方案 |
|------|------|
| **政策草案來源** | 1. 由昱均先提供 2. 參與者分組後自行草擬（Bestian 建議） |
| **討論方式** | - **框架式討論**：先確定 3~4 個政策方向，逐一檢視利弊。- **分組討論**：線上/線下分組（3 組左右），每組配 1 位記錄者。 |
| **分組工具** | - **Teams Breakout Rooms**（待測試）- 亦可使用 **Jitsi** 分組功能作備援 |
| **共筆/記錄工具** | - **Google Doc**（多分頁，即時備份）- **MIRROR**（若需塗鴉牆式視覺化）- **Polis / PocketPolis**（投票、意見地圖） |
| **人力需求** | 每組 1 位「小組長」或記錄者（熟悉流程），建議從社群中挑選。已確認參與：Peter、凱文（線上）、Tim（現場）、Thompson（線上）等。 |
| **時間控制** | - 框架討論 45‑50 分鐘- 開放討論 50‑60 分鐘（可視情況縮短） |

### 四、工具與平台的選擇與測試
| 工具 | 用途 | 優缺點 |
|------|------|--------|
| **Polis / PocketPolis** | 觀察政策意見分布、投票 | 需要先建立儀表板追蹤服務可用性；Polis 近期無法連線 |
| **Mentimeter** | 現場即時投票 | 無法支援分組討論 |
| **Civic Talk** | 政策討論平台（新版） | 正在建置中，預計作為活動懶人包連結 |
| **Google Docs** | 分組共筆、即時備份 | 行動裝置操作友善，版面可分頁 |  
| **MIRROR** | 塗鴉牆式視覺化、議題彙整 | 需要額外設定，較適合大會總結 |  
| **Teams** | 主要會議平台（可與 TWNIC 電腦系統對接） | Breakout 功能尚未測試，要提前驗證 |  


**行動項目**：本週內完成 Teams 分組功能測試；建立 Google Docs 共筆範本；確認所有記錄者（小組長）名單。

---

### 五、與政府/外部機構的合作方向
1. **台北市政府資訊局**  
   - 已建立合作關係，資訊局局長支持開源軟體採購條款。  
   - 可透過 **研考會**（或桃園研考會）切入政策討論，取得政府單位的背書。  
2. **地方政府（桃園、花蓮）**  
   - 針對地方問題（AI 使用指引、教育實驗等）提出「口袋審議」議題。  
3. **GEMIC（多倫多顧問公司）**  
   - 有興趣交流，待安排 9/9 前會議。  

**重點**：合作對象以行政研考會／資訊局為主，較易取得政策推動的窗口；民意代表的預算審議功能較有限。

---

### 六、其他注意事項
* **年齡層差異**：本次參與者年齡跨度較大，需在說明與討論時避免過度專業術語，確保每位參與者都能跟上。  
* **斷線與技術問題**：Polis 近期無法連線；Breakout Room 會有「蕩」的情況，建議使用電腦版 Teams、或改用 Jitsi 作備援。  
* **資料備份**：所有共筆文件需設定版本管理，避免「資料被刪除」的風險（建議使用 GitHub + Google Docs 作雙重備份）。  
* **後續跟進**：活動結束後產出政策行動報告（利弊分析 + 具體建議），並在 Slack / Teams 中分享給所有參與者與合作單位。

---

## 總結
- **核心流程**：議題分享 → 框架式政策討論 → 分組共筆 → 開放式討論 → 總結。  
- **關鍵工具**：Teams（會議 + Breakout）、Google Docs（共筆）、Polis/PocketPolis（意見可視化）、Civic Talk（懶人包）。  
- **人力與時間**：三組分組、每組一位記錄者；全程控制在 150 分鐘內。  
- **待辦**：完成工具測試、確定小組長、準備簡報與政策草案、設置共筆文件、確認合作窗口（研考會、GEMIC）等。  

以上即為 9 月 11 日第二場活動的重點整理。祝活動順利！
